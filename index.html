NIC mode separates physical host cages from logical network links. Single Port / Single Plane: one active link on one plane. Single Port / Dual Plane: one physical host cage is split across two planes (CX-7: 2×200G; CX-8 C8180-style: 2×400G). Dual Port / Dual Plane: two physical NIC ports are used, one per plane (CX-7 dual-port profile: 2×200G; CX-8 C8240-style: 2×400G). The dual-plane switch bandwidth is the same for single-cage split and dual-port modes; the host optic/cable count changes.
AMD default: 8 independent 400G RoCE NIC links per 8-GPU server (1:1 NIC-to-GPU planning mapping) on Cisco N9364E-SG2X-O Silicon One. Change the NIC count, link speed, or plane count to match the selected OEM server. Dual-plane designs should use an even NIC count so each plane receives the same number of links. Spectrum-X is not required.
Choose Compute power budget given to enable the kW field; node/rack count becomes calculated.
SU sizing behavior: selecting a value in Custom SU size automatically switches enforcement to Custom SU size. A 1-unit SU is available for rack-scale systems such as NVL72, so one NVL72 rack can be treated as one scaling unit without being rounded to 4 units. With shared fabric, backend sizing uses the rounded/cabled SU capacity (for example 563 requested nodes at 64-node SU → 9 SUs → 576 fabric-cabled nodes).
Cisco Secure AI Factory CVD guidance uses a 4-node scale unit (32 GPUs on 8-GPU systems) as a common starting point. Larger SU sizes in this tool are engineering planning groups unless separately validated.
Recommended default: Rail-Optimized + Dual Plane for B300/CX8 reference designs. Both remain user-selectable because customer/server NIC topology and validated CVD/RA requirements can differ. AMD MI355X: uses the same server-based sizing framework, defaults to N9364E-SG2X-O (Silicon One) and 8×400G/server, and exposes the actual NIC count, speed, and plane assumptions; no Spectrum-X dependency.
Backend optic choice: DR8 is the long-reach SMF option (500 m). VR8 is the short-reach MMF option (50 m on OM4/OM5) and supports the same 1×800G / 2×400G / 4×200G switch-side breakout model. ConnectX-7 preset: Cisco host side is standardized on QDD-400G-SR8= / MMF. ConnectX-8: NVIDIA validation references base module P/Ns OSFPR-800G-DR8 / OSFP-800G-VR8; BOM and CCW export use Cisco spare-ordering PIDs OSFPR-800G-DR8= / OSFP-800G-VR8=. Rubin NVL8: ConnectX-9 uses NVIDIA MMS4X00-NM-HGX, an 800G twin-port OSFP configured as 2×400G over SMF/2×DR4; the app locks the switch-side family to DR8 pending final interoperability validation.
